# 常见问题

## 现在能用吗

还不能用于实际用途。在 Linux 上从源码编译，两台机器之间能经加密隧道 ping 通，
但没在 Windows 上跑过，没在真实的 NAT 后面测过，也没经过安全审查。没有可下载的二进制。
详见[路线图](/guide/roadmap)。

## 那为什么先做官网

因为这个阶段最需要的是**把设计讲清楚并收到反馈**。
一个能让人三分钟看懂"要造什么、怎么造、为什么这么造"的站点，
比一堆还没定型的代码更能帮到项目 —— 方向错了，代码写得再多也是白写。

## 和 Tailscale 有什么区别

架构上很像，都是 WireGuard 数据面 + 自研控制面。差异在能力编排和按应用选路。
[对比页](/guide/comparison#和-tailscale-的关系)有详细说明，也写了 Tailscale 更好的地方。

**如果 Tailscale 满足你的需求，现在就该用它。**

## 为什么不直接用 WireGuard

因为 WireGuard 只做隧道。它不做节点发现、不做 NAT 穿透、不做中继、不做选路 ——
而这些恰恰是"两台设备自动连上"的全部困难所在。Meshora 要造的就是这些缺失的部分，
隧道本身直接用 WireGuard。见[架构](/guide/architecture)。

## 中继能看到我的数据吗

看不到内容。中继转发的是已经用 WireGuard 加密的报文，
既读不了明文也改不了内容（Poly1305 认证标签会让篡改在对端被丢弃）。

但中继**能看到元数据**：谁在和谁通信、什么时候、流量多大。
所有中继方案都是如此。在意的话可以自建中继。

## 需要公网 IP 吗

普通节点不需要 —— NAT 穿透和中继回退就是为此设计的。

但**中继节点和出口节点需要稳定的公网可达地址**，否则其他节点找不到它。
一张网里至少要有一个这样的节点，或者使用公共中继。

## 支持 CGNAT 吗

这正是要解决的场景之一。CGNAT 下你没有自己的公网 IP，端口转发完全失效，
只能靠打洞加中继兜底。双方都是对称型 NAT 时打洞成功率会明显下降，这种情况下走中继。

## 会收费吗

代码以 MIT 协议开源。至于是否会有托管服务、怎么收费，现在谈这个为时过早。

## 数据会经过你的服务器吗

现在没有任何服务器，因为还没有任何东西在运行。

设计上控制面和中继都**可以自建**。这是个明确的设计约束，不是事后补的开关。

## 为什么用 Rust

内存安全（这是个直接处理不可信网络输入的程序）、无 GC 停顿、交叉编译成熟，
以及 boringtun 本身就是 Rust。详见[架构](/guide/architecture#为什么用-rust)。

## 支持我的系统吗

计划覆盖 Windows、macOS、Linux、Android、iOS、NAS、OpenWrt，共用一份 Rust Core。

**目前一个都不支持**正式使用。Linux 上能从源码编译跑起来，Windows 上只做过编译检查。
第一个目标平台是 Windows。

## 我能帮上什么忙

现阶段最有价值的是**设计层面的反馈**，不是代码 —— 接口契约刚有初版，还会改，提 PR 容易白写。
见[参与进来](/guide/contributing)。

## 名字怎么念

Mesh + ora。取自 mesh network（网状网络）。
