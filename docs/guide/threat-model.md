# 威胁模型

::: warning 当前状态
初版写于 M0，M1 的实现逐条对照过：哪些要求已经落地、哪些还没有，见[对设计的要求](#对设计的要求)。
实现没有经过任何安全审查。
:::

一个直接处理不可信网络输入的程序，安全不能靠事后补。这一页把威胁一条条摆出来，
**包括防不住的** —— 知道边界在哪，比相信它无懈可击有用。

如果你发现了这里没写到的问题，请按 [SECURITY.md](https://github.com/Kerxs/meshora/blob/main/SECURITY.md) 私下报告。

## 要保护什么

| 资产 | 丢了意味着什么 |
| --- | --- |
| **节点私钥** | 别人能冒充这个节点。过去的会话有 WireGuard 的前向安全保护，解不开 |
| **通信内容** | 被读到，或者被篡改 |
| **元数据** | 谁和谁在通信、什么时候、流量多大，以及各自的公网地址（大致能推出位置） |
| **成员关系与访问控制** | 谁在这张网里、谁能访问谁。被篡改就等于有人混了进来 |
| **可用性** | 连不上 |

## 信任假设

下面的结论都建立在这几条假设上。哪条假设不成立，建立在它上面的结论也就不成立：

- **控制面被信任负责成员与公钥分发。** 节点靠控制面知道"某某的公钥是什么"。这是整套设计里信任最集中的地方，
  它被攻陷的后果[下文](#恶意或被攻陷的控制面)单独讨论。控制面可以自建，信不过别人就自己架。
- **中继不被信任。** 只指望它尽力转发，内容上一概不信它。
- **节点所在的设备没有被攻陷。** 攻击者拿到了设备的管理员权限，这台设备上的一切都保不住。
- **密码学原语和它们的实现可靠**：Curve25519、ChaCha20-Poly1305、BLAKE2s，以及 boringtun。自己不写密码学。

## 按攻击者逐个看

### 网络路径上的攻击者

公共 Wi-Fi、运营商、路上的任何一台路由器。它**能**观察、丢弃、注入、重放、篡改经过的报文。

- **拿不到**：通信内容。WireGuard 报文加密且带认证，改过的会在对端被丢弃，重放的会被计数器挡掉。
- **看得到**：哪个公网地址在和哪个通信、报文的大小和时间，以及"这是 WireGuard / Meshora 流量"——
  报文格式本身就能被识别。报文大小尤其精确：boringtun 不做 WireGuard 规范里的 16 字节填充，
  密文长度就是明文长度加 32。
- **设计上的应对**：
  - 数据面不做漫游，发送路径只由控制面切换（见[接口契约](/guide/interfaces#_3-发送路径只由控制面决定)）。
    扣下报文、换个源地址再放出去，改不了路径
  - 控制报文必须经过认证（R3）。否则伪造一条"我的新地址是某某"，就能把流量引走
  - UDP 被挡时退到中继。这也是为什么中继的传输要考虑能不能穿过只放行 443 端口的网络
- **剩余风险**：它总能把流量全部挡掉。如果连到中继的路也被挡了，那就是连不上。

### 恶意中继

中继可能是别人架的。它**能**看到经过它的报文，也能决定转不转发。

- **拿不到**：内容，理由同上 —— 它转发的是 WireGuard 报文，改不了，重放了也会被计数器挡掉。
- **看得到**：元数据。哪两个节点在通信（它得知道报文该交给谁）、时间、流量大小，以及双方的公网地址。
- **设计上的应对**：
  - 节点连中继时要认证身份（R6）。否则谁都能冒领发给某个节点的报文 —— 读不了，但能让那个节点收不到
  - 中继只服务名单里的节点，别人没法白用它的带宽
- **剩余风险**：
  - 元数据暴露是所有中继方案的共同性质。在意的话就自建中继
  - 中继丢包或拖延，**M1 的控制面察觉不到**：它只探测直连，不探测中继。直连一旦打通会切走；
    打不通时就只能受着

### 恶意或被攻陷的控制面

**这是整套设计里爆炸半径最大的一处**，需要说清楚。

控制面告诉每个节点"网里有谁、各自的公钥是什么"。一个恶意的控制面**能**：

- 把某个节点的公钥换成自己的，对它做中间人。节点会以为自己在和正确的对端说话
- 把自己的节点塞进网里，或者改掉访问控制
- 看到整张网的拓扑，以及每个节点的公网地址

**以现在的设计，这些都防不住。** 集中分发公钥的方案都有这个问题，Tailscale 也一样，它后来用 Tailnet Lock 做了缓解。
眼下的应对只有两条：

- 控制面可以自建，把信任留在自己手里
- 节点和控制面之间的握手会认证控制面的身份（见[身份认证](#身份认证)），网络上的攻击者冒充不了它

怎么降低对控制面的信任，排在[开放问题](#开放问题)的第一条。

### 网内的恶意节点

一个合法加入、但不怀好意（或者已经被攻陷）的节点。

- **能**：访问访问控制允许它访问的一切。**M2 做出 ACL 之前，这意味着网里的所有节点。**
- **不能**：冒用别的节点的 overlay 地址。WireGuard 会丢弃源地址不在对方 AllowedIPs 里的报文，
  而 AllowedIPs 由控制面分配，节点自己说了不算。
- **看得到**：网里所有成员的公网端点 —— NetMap 会把它们发给每个成员，打洞要用。
  换句话说，入网的节点彼此知道对方大致在哪
- **还要防**：
  - 上报一堆别人的地址当作自己的端点，让其他节点往那里发探测报文。协调服务把每个节点的端点
    限制在 16 个以内，探测报文也很小，但它确实能被当成一个很小的反射源
  - 声明中继或出口能力，把别人的流量吸过来；在虚拟局域网里乱发广播。
    前者靠能力授权（M3），后者靠广播域和限速（M2）

### 本机上的其他进程

节点守护进程需要管理员权限（改路由、开虚拟网卡），同一台机器上的普通进程不能借它提权：

- 私钥文件只有守护进程能读
- 本地管理接口（给命令行和图形界面用）必须做访问控制：Windows 上是命名管道的 ACL，Unix 上是 socket 的文件权限（R7）

### 私钥泄漏、设备丢失

拿到私钥就能冒充这个节点，直到这把公钥被吊销。WireGuard 的前向安全保证过去的会话解不开。

应对办法是控制面吊销这把公钥，所有节点随后拒绝它。**吊销要多久才能传到每个节点**，还是开放问题。

### 供应链

依赖、工具链、CI 都可能被投毒。

- 依赖尽量少，每加一个都要在 `Cargo.toml` 里写明理由。依赖树里的大头是 boringtun，
  以及它带进来的一批密码学 crate —— 这是"不自己写密码学"的代价，也正是这条规矩的用意
- `Cargo.lock` 入库，CI 一律加 `--locked`；Rust 工具链版本固定
- Rust 的 CI 只拿只读权限
- 站点用的 VitePress 依赖树要大得多，但它只影响站点，不会进节点程序
- **剩余风险**：GitHub Actions 按大版本号引用，没有按提交哈希固定。大版本标签要是被人改了指向，CI 就会跑别人的代码。

## 身份认证

节点怎么向控制面证明"我是这把公钥的主人"？**用 Noise IK 握手，而不是签名。**

WireGuard 的密钥是 X25519，只能做密钥交换，不能直接签名。想要签名，有三条路，各有各的问题：

| 方案 | 问题 |
| --- | --- |
| 另备一对 Ed25519 密钥专门签名 | "认证和加密用同一对密钥"不成立了，还要多管一把密钥 |
| 身份用 Ed25519，WireGuard 密钥由它换算出来 | 同一个秘密既签名又做 DH，属于跨协议复用，不是好做法 |
| XEdDSA，直接拿 X25519 密钥签名 | 不是标准做法，经过充分审查的实现很少 —— 等于自己写密码学 |

Noise IK 绕开了这个问题：节点拿 WireGuard 用的那对静态密钥，和控制面跑一次握手，
握手能完成就证明它持有私钥。好处有这几个：

- **原语和 WireGuard 是同一套**（Curve25519、ChaChaPoly、BLAKE2s）。WireGuard 自己的握手就是 Noise 的 IKpsk2 变体，不引入新的密码学
- **双向认证**：按设计，节点事先就知道控制面的公钥（随邀请或配置下发），所以同一次握手也认证了控制面
- 握手一完成就有了加密信道，控制面的通信不必再依赖 TLS 证书体系
- 有先例：Tailscale 的控制协议同样用 Noise IK 认证节点（它用的是一把专门的机器密钥，不是 WireGuard 那把）

代价有两个：

- **给不出能转交第三方验证的签名**，比如"这个节点声明了中继能力"这类声明
- **换密钥就等于换身份**。公钥即身份，轮换 WireGuard 密钥之后，这个节点在网里就是另一个人了。
  Tailscale 把设备身份（机器密钥）和 WireGuard 密钥分成了两把，WireGuard 密钥轮换时设备身份不变

这两点将来需要时都能增量解决：要么加一把签名密钥，要么把身份和 WireGuard 密钥分开。
到那时加进来的东西有明确的用途，而不是现在就多一把用不上的密钥。

同一把节点密钥用在了几种协议里：WireGuard 的握手、控制通道和中继通道的 Noise IK、节点之间控制报文的
Noise K。它们靠各自不同的 Noise 模式和 prologue 做域分离 —— 一种协议里的消息拿到另一种协议里解不开。
协调服务顺带跑中继时，两边共用协调服务的密钥，也是靠这一点隔开。

还有一处细节必须注意：**IK 的第一个握手包可以被重放。** 攻击者录下某个节点的首包，之后原样发给控制面，
控制面分不出真假。WireGuard 为此在首包里放了时间戳；控制面的做法更简单：
**握手完成之前不因为首包做任何有副作用的事**，有副作用的请求一律等握手完成、走加密信道再发。

## 对设计的要求

从上面推出来的硬性要求，以及 M1 实现到了哪一步。"有测试"指的是有专门验证这一条的测试。

| 编号 | 要求 | 现在 |
| --- | --- | --- |
| R1 | 节点和控制面之间用 Noise IK 认证，握手完成前不产生任何副作用 | 已实现，有测试：协调服务和中继都要等到第一条加密消息才登记连接 |
| R2 | 数据面不做漫游，发送路径只由控制面切换 | 已实现，有测试 |
| R3 | 控制报文一律要认证，未经认证的报文不能改变任何状态，还要限速 | 已实现：Noise K 认证，陌生发送方在任何 DH 之前就丢；协调服务的探测端点和节点侧都限速，每秒 200 条 |
| R4 | 同一个网段只能分给一个 peer | 已实现，有测试 |
| R5 | 私钥不出数据面，接口里没有读私钥的方法 | 已实现（接口里没有这样的方法）。控制面持有同一把私钥的另一份，从密钥文件读 |
| R6 | 节点连中继时要认证身份 | 已实现，有测试：中继按节点密钥认证，只服务名单里的节点 |
| R7 | 本地管理接口做访问控制，私钥文件只有守护进程能读 | 部分：私钥文件对别人可读时只提醒不拒绝；本地管理接口还不存在 |
| R8 | 依赖尽量少，锁文件入库，CI 加 `--locked` | 已经在做 |

## 不防什么

- **匿名。** 不隐藏你是谁、在和谁通信。需要匿名请用 Tor 这类工具。
- **流量识别。** 别人看得出这是 WireGuard / Meshora 流量。它不是翻墙工具，也不打算伪装。
- **已被攻陷的设备。** 攻击者拿到了设备的管理员权限，这台设备上的一切都保不住。
- **量子计算。** X25519 不抗量子。WireGuard 的预共享密钥（PSK）能额外加一层对称加密的保护，
  要不要用、怎么分发，是开放问题。

## 开放问题

1. **怎么降低对控制面的信任。** 比如让用户带外核对公钥（类似 Signal 的安全码），
   或者由离线保管的管理员密钥签署成员变更（类似 Tailnet Lock）
2. **身份和 WireGuard 密钥要不要分开**，好让密钥轮换不影响身份
3. **要不要用 WireGuard 的预共享密钥**，用的话怎么分发
4. **吊销怎么传播**：一把公钥被吊销后，多久能让每个节点都拒绝它？离线的节点回来时怎么办？
5. **能不能让中继少知道一点**，比如不让它知道报文是从哪个节点来的
6. **GitHub Actions 要不要按提交哈希固定**
