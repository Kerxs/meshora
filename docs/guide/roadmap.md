# 路线图

## 当前状态：设计阶段

**所有功能项的状态都还是「设计中」。仓库里没有可运行的网络引擎，也没有可下载的二进制。**

这一页不打算粉饰进度。下面每一项后面的状态标记是真实的：

| 标记 | 含义 |
| --- | --- |
| 设计中 | 在讨论方案，还没动代码 |
| 开发中 | 有代码在写，但还不能用 |
| 可用 | 能跑，有人在用 |

截至今天，**只有 M0 地基里的几项离开了「设计中」**。它们是地基，不是功能：
workspace 里的代码只定义接口，不收发任何一个报文。

## M0 地基

| 项目 | 状态 |
| --- | --- |
| 仓库、官网、设计文档 | 可用 |
| Rust workspace 与 crate 划分 | 可用 |
| 控制面 / 数据面接口契约 | 开发中 |
| 威胁模型 | 可用 |

- **crate 划分**已经定了，但 workspace 里目前只有两个 crate。其余的等各自有代码可写时再建，
  见[接口契约 · crate 划分](/guide/interfaces#crate-划分)。
- **[接口契约](/guide/interfaces)**的初版已经写成 trait 和类型，但还没有实现来检验它。
  M1 写数据面时一定会改，所以是「开发中」。
- **[威胁模型](/guide/threat-model)**是初版，M1 实现时会逐条对照。

## M1 打通主干

目标：**两台 Windows 机器，一条加密隧道，能互相 ping 通。**

| 项目 | 状态 |
| --- | --- |
| 节点身份与注册（公钥即身份，Noise IK 认证） | 设计中 |
| boringtun 集成 | 设计中 |
| wintun 虚拟网卡 | 设计中 |
| 控制面最小实现（发现 + 密钥分发） | 设计中 |
| 端点探测（类 STUN） | 设计中 |
| UDP 打洞协调 | 设计中 |
| Relay 回退 | 设计中 |

这是整个项目最关键的里程碑。**M1 跑通之前，其余全是纸面工作。**

## M4 分应用路由

| 项目 | 状态 |
| --- | --- |
| 按 IP / 端口分流 | 设计中 |
